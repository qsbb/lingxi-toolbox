# 凌溪工具箱（LingXi Toolbox）开发文档 v1.0

> **一句话定位**：把「音频快切」「服务器监控」这类高频桌面小工具收进一个壳，用 iOS 26 Liquid Glass 风格做 UI，以「壳 + 平台服务 + 插件模块」架构留出后续开发空间。
> **技术底座**：.NET 8（LTS）+ WPF + [lepoco/wpfui](https://github.com/lepoco/wpfui)（MIT）。
> **遗产来源**：
> ① [qsbb/servermonitor](https://github.com/qsbb/servermonitor)（MIT，TRSS-Yunzai 多服务器监控插件，Windows 端为 agent）；
> ② 本机局域网开发机上的 `QuickAudioSwitch`（Windows 源码样本）（.NET 8 WPF，CoreAudio 纯 COM 互操作）。
> **调研快照**（本工作区可直接查看源码）：`lingxi_research/servermonitor/`、`lingxi_research/qas2/QuickAudioSwitch/`。
> **关联文档**：本工作区已有《iOS26-LiquidGlass-Unity-USS-设计规范.md》，本文档第 6 章的设计令牌与其保持一致，仅把落地目标从 Unity USS 换成 WPF。

## 1. 项目概述

### 1.1 定位

凌溪工具箱是一个 **Windows 桌面常驻工具集合应用**：

- **一个壳**：左侧导航 + 玻璃质感主窗口，托盘常驻，热键唤起；
- **一组内置工具**：首发两枚——凌溪·音频（设备快切）、凌溪·监控（服务器状态仪表盘）；
- **一套插件 SDK**：未来新工具以模块形式接入，壳不改动。

### 1.2 目标（Goal）

| 编号 | 目标 | 验收标准 |
|---|---|---|
| G1 | 整合两份遗产 | AudioSwitch 功能 ≥ QuickAudioSwitch 现状；Monitor 能消费 servermonitor agent 上报并本地可视化 |
| G2 | iOS 26 玻璃风格 UI | 三层材质模型落地（Mica 窗体 / Acrylic 浮层 / Glass 卡片），明暗双主题 |
| G3 | 可扩展 | 新工具 = 新增一个模块程序集 + `lxmod.json`，壳零改动 |
| G4 | 可分发 | Velopack 打包，单安装器，增量自动更新 |
| G5 | 不重复造轮子 | UI 基座用 [lepoco/wpfui](https://github.com/lepoco/wpfui)，MVVM 用 [CommunityToolkit.Mvvm](https://github.com/CommunityToolkit/dotnet)，托盘用 [H.NotifyIcon](https://github.com/HavenDV/H.NotifyIcon)，更新用 [Velopack](https://github.com/velopack/velopack)（完整清单见第 16 章） |

### 1.3 非目标（Non-Goal）

- ❌ 不做跨平台（macOS/Linux 不在 v1 范围；架构上不为跨平台牺牲 Windows 集成深度）；
- ❌ 不重写 servermonitor 的 QQ 出图渲染（Yunzai 侧功能保持原样，工具箱只做"本地消费端"）；
- ❌ v1 不实现音频峰值表/均衡器（属于 LX.Audio 后续增强，见 8.1）；
- ❌ 不引入账号体系/云同步（默认本地、离线可用是架构公理之一）。

### 1.4 名词表

| 名词 | 含义 |
|---|---|
| 壳（Shell） | `LX.App`，主进程、主窗口、导航、托盘、主题宿主 |
| 模块（Module） | 实现 `ILxToolModule` 的工具单元（音频、监控、未来工具） |
| 平台服务 | 设置/日志/托盘/热键/通知/更新等注入给模块的公共服务 |
| LX Hub | 监控模块内置的本地 HTTP 收数端，实现 servermonitor 上报协议 |
| agent | servermonitor 的采集进程（`agent.mjs` / `servermonitor-agent.exe`） |
| 快照（Snapshot） | agent 上报的 v:1 JSON 状态包（契约见 9.4 / 附录 D） |

## 2. 第一性原理推导

### 2.1 用户真正要的是什么

用户手上不是一个"软件需求"，而是**两类高频小操作**：

1. **「把声音切到另一个设备」**——发生在插拔耳机、开会切音箱时，要求 3 秒内完成；
2. **「看看我那几台机器还活着吗」**——发生在日常巡检，要求一眼看完 CPU/内存/磁盘/温度/网络。

这两个需求的共同本质是：**一组"打开即用、用完即走"的桌面小工具**。追问三层：

- 为什么两个工具各自做一个 exe 不好？→ 每个工具都要重复实现：托盘常驻、开机自启、设置存取、日志、更新、主题。QuickAudioSwitch 的自包含单文件 exe 有 **162MB**，其中约 160MB 是 .NET 运行时——每加一个工具就重复付一次这个成本。
- 为什么工具集合的核心是"壳"？→ 因为上面列的每一项都是**横切关注点**，只应实现一次，注入给所有工具。
- 为什么界面要统一？→ 工具切换时用户认知成本最低的方式是"同一个世界的不同房间"，而不是"一堆长得互不认识的窗口"。

### 2.2 本质拆解

任何"桌面工具箱"都可以拆成且只需三层：

```
┌─────────────────────────────────────────────┐
│ 壳（Shell）                                  │
│   容器：窗口、导航、主题、托盘、生命周期        │
├─────────────────────────────────────────────┤
│ 平台服务（Platform Services）                 │
│   设置 / 日志 / 热键 / 通知 / 更新 / 单实例     │
│   ← 所有工具都需要、且实现方式与业务无关        │
├─────────────────────────────────────────────┤
│ 工具（Modules）                              │
│   音频快切 / 服务器监控 / 未来的工具…           │
│   ← 只含领域逻辑，不含横切关注点                │
└─────────────────────────────────────────────┘
```

**结论**：做一个单体应用等于把三层焊死；做一堆独立 exe 等于把中间层复制 N 份。唯一既消重又可扩展的形态是 **壳 + 插件**。

### 2.3 四条架构公理（后续所有设计不得违反）

| # | 公理 | 推理由 |
|---|---|---|
| A1 | **依赖方向单向**：壳不依赖模块，模块只依赖 SDK 契约 | 否则"加工具就要改壳"，可扩展性不成立 |
| A2 | **平台能力全部经接口注入**（`ISettingsStore`、`ILogger`、`ITrayService`…） | 模块可单测；服务实现可替换（如换更新渠道） |
| A3 | **数据契约与 UI 解耦**（快照 JSON、设备模型是模块内核，视图只消费） | UI 风格迭代（玻璃 v2、v3）不动领域代码 |
| A4 | **默认本地、离线可用**；网络能力（Yunzai 转发、更新）全部可选可关 | 工具箱是私人物品，不是 SaaS 客户端 |

### 2.4 从公理到落地决策的映射

| 公理 | 落地 |
|---|---|
| A1 | `ILxToolModule` 契约 + `plugins/` 目录反射加载（第 10 章） |
| A2 | `Microsoft.Extensions.Hosting` 容器，模块构造注入服务（7.x） |
| A3 | `LX.Audio.Core` / `LX.Monitor.Core` 与视图层分程序集（第 8、9 章） |
| A4 | 所有设置落 `%LocalAppData%\LingXi\`，更新/转发默认关闭或显式配置 |

### 3.2 servermonitor 资产清单

| 资产 | 内容 | 复用决策 |
|---|---|---|
| **上报协议** | `POST /servermonitor/report`（别名 `/server-monitor/report`），头 `X-SM-Token`，体为快照 JSON | ✅ **直接实现**——LX Hub 做本地收数端（9.3） |

## 4. 总体架构

### 4.1 分层视图

```
┌────────────────────────────────────────────────────────────────┐
│ LX.App（壳）                                                     │
│  FluentWindow + NavigationView │ 托盘 │ 热键唤起 │ 单实例 │ 更新   │
├────────────────────────────────────────────────────────────────┤
│ LX.Core（平台服务）                                               │
│  ISettingsStore │ ILogger(Serilog) │ ITrayService │             │
│  IHotkeyService │ INotifyService │ IUpdateService │ IAutoStart   │
├─────────────────── 依赖注入（Microsoft.Extensions.Hosting） ────┤
│ LX.Module.Sdk（契约层，唯一允许被模块依赖）                         │
│  ILxToolModule │ ILxModuleContext │ lxmod.json schema           │
├────────────────────────────────────────────────────────────────┤
│ 内置模块（与第三方模块同规则，无特权）                               │
│  LX.AudioSwitch ── LX.Audio.Core（CoreAudio 互操作）              │
│  LX.Monitor ────── LX.Monitor.Core（LX Hub + 采集引擎）           │
├────────────────────────────────────────────────────────────────┤
│ LX.Ui（设计系统：令牌 + 玻璃控件 + 主题）                          │
└────────────────────────────────────────────────────────────────┘
```

### 4.2 解决方案结构

```
lingxi-toolbox/
├─ LingXi.sln
├─ src/
│  ├─ LX.App/              # 壳：入口、主窗口、导航、托盘、模块装载
│  ├─ LX.Core/             # 平台服务实现
│  ├─ LX.Module.Sdk/       # 模块契约（纯接口 + POCO，零第三方依赖）
│  ├─ LX.Ui/               # 玻璃设计系统（令牌/样式/控件，依赖 wpfui）
│  ├─ LX.Audio.Core/       # 音频领域服务（无 UI 依赖，可单测）
│  ├─ LX.AudioSwitch/      # 音频模块（View + ViewModel）
│  ├─ LX.Monitor.Core/     # 监控领域服务：LX Hub、快照模型、采集引擎
│  └─ LX.Monitor/          # 监控模块（View + ViewModel）
├─ tests/
│  ├─ LX.Core.Tests/
│  ├─ LX.Audio.Core.Tests/
│  └─ LX.Monitor.Core.Tests/
├─ plugins/                # 外部模块加载目录（构建输出 + 第三方模块）
├─ docs/                   # 本文档及后续设计文档
└─ scripts/                # 打包、发布脚本
```

### 4.3 进程模型

- **单实例**：命名 Mutex `LingXi.Toolbox.SingleInstance`；二次启动时通过命名管道把"显示主窗口"消息转给首实例后退出；
- **托盘常驻**：关窗默认最小化到托盘（可配置为真退出）；
- **agent 子进程**（监控引擎 A）：由 `LX.Monitor.Core` 托管 `servermonitor-agent`，随工具箱启停，崩溃自动重启（退避 1s→2s→5s→30s 封顶）；
- **无系统服务依赖**：v1 不装 NSSM/计划任务，避免安装器提权——工具箱自己的开机自启走 `HKCU\...\Run`（无需管理员）。

## 5. 技术选型

### 5.1 决策矩阵

| 维度（权重） | WPF + wpfui | WinUI 3 | Tauri/Web 前端 | Avalonia |
|---|---|---|---|---|
| 玻璃质感可达性（25%） | ★★★★ Mica/Acrylic + 自绘玻璃卡片 | ★★★★★ 原生 Composition | ★★★ `backdrop-filter`（性能一般） | ★★★★ |
| QAS 代码复用度（25%） | ★★★★★ 同栈原样搬 | ★★★★ XAML 需改写 | ★★ 仅服务层可复用 | ★★★ |
| Windows 深度集成（托盘/COM/热键）（20%） | ★★★★★ | ★★★★ | ★★★ | ★★★★ |
| 生态成熟度/踩坑成本（15%） | ★★★★★ 十年生态 | ★★★ 较新 | ★★★ | ★★★★ |
| 打包与分发（10%） | ★★★★ Velopack 原生支持 .NET | ★★★ MSIX 限制多 | ★★★★ | ★★★ |
| 跨平台（5%，低权重——见 1.3） | ★ | ★ | ★★★★★ | ★★★★★ |
| **加权结论** | **采用** | 备选（v2 再评） | 否 | 备选（跨平台时再评） |

### 5.2 结论

**.NET 8（LTS）+ WPF + [lepoco/wpfui](https://github.com/lepoco/wpfui)（MIT）**。决定性理由：

1. QuickAudioSwitch 就是 `net8.0-windows` + WPF，`AudioDeviceService.cs` 可零改动搬运；
2. wpfui 提供 `FluentWindow`、Mica/Acrylic 窗口背景、`NavigationView`、`SymbolIcon` 图标体系——正是玻璃 UI 需要的骨架，且有 [Window Backdrop](https://deepwiki.com/lepoco/wpfui/5.3-window-backdrop) 等成熟文档；
3. servermonitor agent 是外部进程，与壳的技术栈解耦，不构成选型约束。

### 5.3 运行时

- 目标框架：`net8.0-windows10.0.17763.0`（Win10 1809+；Mica 仅在 Win11 生效，Win10 自动降级 Acrylic/纯色，见 6.2）；
- 语言：C# 12，`<Nullable>enable</Nullable>`，`<ImplicitUsings>enable</ImplicitUsings>`；
- 发布：`win-x64` 单一 RID。

## 6. UI 设计系统：iOS 26 Liquid Glass 的 Windows 落地

> 本章与工作区《iOS26-LiquidGlass-Unity-USS-设计规范.md》同源：同样的分层铁律、同样的令牌语义，落地目标换成 WPF。**铁律复述：玻璃只属于控制层（导航/工具栏/按钮/弹层），内容层（列表/正文）保持实色；避免 glass-on-glass 堆叠。**

### 6.1 材质三层模型（WPF 版）

| 层级 | iOS 26 对应 | WPF 实现 | 用途 |
|---|---|---|---|
| **L0 窗体材质** | 系统玻璃 | Win11：`WindowBackdropType.Mica`；Win10：降级 `Acrylic`，再降级纯色 `#F2F2F7/#000000`（wpfui `WindowBackdrop.ApplyBackdrop` 一行搞定） | 主窗口、对话框底 |
| **L1 浮层材质** | `.regular` 玻璃 | Acrylic（亚克力）或 `LxGlassCard` | 托盘快切浮窗、通知卡、下拉 |

### 6.2 设计令牌（`LX.Ui/Themes/Tokens.xaml`）

色彩（对齐 Unity 规范令牌，同时吸收 QAS 现有色板）：

```xaml
<Color x:Key="LxTextPrimary">#FF1C1C1E</Color>
<Color x:Key="LxTextSecondary">#993C3C43</Color>   <!-- 60% 黑 -->
```

玻璃填充/描边（核心参数，直接可用）：

```xaml

<SolidColorBrush x:Key="LxGlassFill"  Color="#29FFFFFF"/>
<SolidColorBrush x:Key="LxGlassFillHover" Color="#3DFFFFFF"/>
<!-- 描边：顶亮底暗的纵向渐变，模拟玻璃边缘高光 -->
<LinearGradientBrush x:Key="LxGlassBorder" StartPoint="0,0" EndPoint="0,1">
    <GradientStop Color="#66FFFFFF" Offset="0"/>
    <GradientStop Color="#14FFFFFF" Offset="1"/>
</LinearGradientBrush>
<!-- 软阴影：沿用 QAS CardShadow 参数，与遗产 UI 观感连续 -->
<DropShadowEffect x:Key="LxCardShadow" BlurRadius="24" ShadowDepth="5"
                  Direction="270" Opacity="0.12" Color="#53637D"/>
```

圆角阶梯（与 Unity 规范 3.2 节一致）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `LxRadiusControl` | 10 | 输入框、标准控件、小卡片 |
| `LxRadiusCard` | 16 | 中型卡片 |
| `LxRadiusSheet` | 20 | 大浮层、主内容容器 |
| `LxRadiusCapsule` | 999 | 按钮、状态 pill（实际=高/2） |
| 嵌套规则 | `内层 = 外层 − padding`（concentric） | 卡片内嵌图/子卡片必须遵守 |

动效令牌：`LxDurationFast=0.15s`、`LxDurationNormal=0.25s`、缓动 `CubicEase EaseOut`；悬停位移 ≤2px，缩放 ≤1.02——**克制优先**。

### 6.3 核心控件规格

**`LxGlassCard`**（L2 材质本体，组合实现不造新渲染管线）：

```xaml
<Border CornerRadius="{DynamicResource LxRadiusCard}"
        Background="{DynamicResource LxGlassFill}"
        BorderBrush="{DynamicResource LxGlassBorder}"
        BorderThickness="1"
        Effect="{DynamicResource LxCardShadow}">
    <!-- 顶部高光带：一条 40%→0 渐变的 1px 高亮，模拟玻璃上缘反光 -->
    <!-- 可选：2% 不透明度的噪点/斜纹 TextureBrush，增加材质感 -->
    <ContentPresenter/>
</Border>
```

**`LxPillButton`**：胶囊形（圆角=高/2），三态：常态 `LxGlassFill` / 悬停 `LxGlassFillHover` / 按压 `Opacity=0.82` + `Scale=0.98`；主按钮变体 `AccentPillButton` 用 `LxTintBlue` 填充白字——**一屏只允许一个主按钮**。

**`LxStatusPill`**：监控/音频通用的状态胶囊（在线绿 / 已拔出橙 / 离线红），语义色只出现在 pill 内，不大面积铺色。

**`LxMetricRing`**：监控仪表盘的 CPU/内存环形指示器——弧线 + 中心百分比，弧线端点圆头，非 100% 时轨道用 `LxGlassFill`。

**图标**：优先 wpfui `SymbolIcon`（Fluent 图标体系）；设备/机器类型图标用 24×24 圆形底 + 单色 glyph（沿用 QAS 的 `♫` 圆形图标思路，换成 `SymbolIcon` 的 `Speaker2`/`Desktop` 等）。

### 6.4 主题与无障碍

- 明暗主题：wpfui `ApplicationThemeManager.Apply(...)` + 令牌字典双份（`Tokens.Light.xaml`/`Tokens.Dark.xaml`）；跟随系统为默认；
- 高对比模式：系统开启时，玻璃填充降级为实色 + 描边加深（对应 Apple "Increase Contrast"）；
- 减少动态：系统 `SPI_GETCLIENTAREAANIMATION` 关闭时，禁用所有位移/缩放动效，只保留透明度渐变。

## 9. 模块设计：凌溪·监控（LX.Monitor）

### 9.1 功能定位

servermonitor 现状是「agent 上报 → Yunzai 渲染 PNG → QQ 里发 `#服务器状态` 看图」。工具箱补的是**桌面实时消费端**：

```
                 ┌──────────────── Yunzai（QQ 出图，现状不动）◄── 转发（可选）
                 │                          ▲
agent(win/linux/mac)──POST──► LX Hub(本地收数端)──► 内存快照表 ──► 桌面仪表盘（实时刷新）
   本机则可用引擎B原生采集 ────┘                └──► 离线判定 / 阈值告警 ──► 托盘通知
```

价值：不用开 QQ/不用发命令，托盘一键看全部机器；且与 Yunzai **协议同源**——同一个 agent 不用改，指到工具箱即可。

### 9.2 双引擎采集

| | 引擎 A：托管外部 agent | 引擎 B：原生采集器 |
|---|---|---|
| 来源 | 复用 `agent/agent.mjs`（pkg 打出的 `servermonitor-agent.exe`，或本机 Node + 源码） | `LX.Monitor.Core` 内新写 |
| 覆盖 | 全平台全部指标（含 NVIDIA GPU、Linux RAPL 功耗） | CPU/内存/磁盘/网络（`System.Diagnostics`+WMI）；温度/风扇/功耗经 `LibreHardwareMonitorLib` |
| 依赖 | Node 18+ 或 pkg exe（agent 仓库 `build:exe` 已备好 `pkg --targets node18-win-x64`） | 温度类需管理员/内核驱动（LibreHardwareMonitor 的 WinRing0） |
| 适用 | **默认**（与 Yunzai 数据 100% 同源） | 本机轻量场景、不想装 Node 时 |

- 引擎 A 托管参数沿用官方：`SM_NAME / SM_TOKEN / SM_REPORT_URL=http://127.0.0.1:2536/servermonitor/report / SM_INTERVAL=10 / SM_SLOW_INTERVAL=30 / SM_TIMEOUT=5000`；
- 引擎 B 输出**同一快照契约**（`v:1`），直接喂给 Hub 内存表，UI 无感知；
- 两引擎可并存：引擎 B 负责本机、引擎 A 们负责远端机器。

### 9.3 LX Hub 本地收数端

- 实现：`HttpListener`（或 Kestrel 精简宿主）监听 `127.0.0.1:2536`（端口可配），路由严格实现协议：`POST /servermonitor/report` + 别名 `/server-monitor/report`，校验 `X-SM-Token`；
- token 管理：Hub 首次启动生成 `sm_<32hex>`（与 install 脚本同款随机 16 字节 hex），展示在监控设置页供 agent 配置；维护多 token→机器名映射（对齐 model.js 的 `configIndexByToken`）；
- 快照表：`ConcurrentDictionary<name, Snapshot>` 只存最新 + 收到时刻；**离线判定沿用 `offline_timeout=30s`**（可配）；
- 持久化：内存为主，可选把最近快照写 `%LocalAppData%\LingXi\monitor\last-snapshots.json` 供重启恢复；
- **转发中继（可选开关）**：Hub 收到上报后异步 `POST` 到配置的 Yunzai 地址（同一 body、同一 token）→ 一份 agent 同时喂 QQ 出图和桌面仪表盘，互不干扰。

### 9.4 快照契约（v:1，冻结兼容——逐字段表见附录 D）

UI 数据模型 `SnapshotDto` 与 JSON 1:1 映射（System.Text.Json，`JsonNumberHandling.AllowReadingFromString`，全字段可空宽容解析）。**升级纪律**：agent 契约演进时以 `v` 字段区分，Hub/UI 对未知字段只忽略不报错（向前兼容）。

### 9.5 仪表盘界面规格

- **总览页**：机器卡片网格（`LxGlassCard`，`page_size=8` 对齐原配置，超出分页/滚动）：
  - 卡头：主机名 + 状态 pill（在线绿/离线红，离线显示"最后在线 xx 前"）；
  - 卡体：`LxMetricRing`×2（CPU%、内存%）+ 磁盘用量条（取使用率最高盘）+ 网速行（`↓ rxSec ↑ txSec` MiB/s）+ 温度行（有则显示）；
  - 卡脚：OS 发行版 + 架构 + 上报间隔；
- **详情页**（点卡进入）：GPU 列表（型号/利用率/显存/温度/功耗）、全部磁盘、负载 1/5/15（Windows 为 null 时隐藏）、历史迷你折线（内存中保留最近 N=360 点 × 10s ≈ 1 小时）；
- **刷新**：Hub 收到上报即事件推送 UI（`ObservableCollection` 差量更新），无需轮询。

### 9.6 告警

- 规则 MVP：机器离线 / CPU 连续 3 次 >90% / 磁盘任一盘 >90% / 温度 >85℃；
- 冷却：`alert.cooldown=120s` 沿用原配置，同机器同规则在冷却内不重复通知；
- 通道：`INotifyService` 托盘气泡；告警历史进日志。

### 9.7 设置页项

| 设置 | 默认 | 说明 |
|---|---|---|
| Hub 监听端口 | 2536 | 与官方 install 脚本示例一致 |
| Hub token | 自动生成 | 可重置，重置后旧 token 失效 |
| 离线阈值 | 30s | 对齐 `offline_timeout` |
| 转发到 Yunzai | 关 | 开启需填 URL + token |
| 采集引擎 | A（本机也用 agent） | A/B 切换 |
| 告警开关/阈值/冷却 | 开 / 上文值 / 120s | |

```jsonc
  "sdk": "1.0",                    // 编译时使用的 SDK 主版本
  "entry": "LX.AudioSwitch.dll",   // 含 ILxToolModule 实现的程序集
  "icon": "Speaker2",
  "permissions": ["settings", "tray", "hotkey"],   // 声明式权限（v1 仅审计展示）
  "builtin": true                  // 内置模块标记
}
```

### 10.3 发现与加载

1. 内置模块：`src/` 编译输出直接随壳发布，`modules.json` 清单登记；
2. 外部模块：`plugins/<id>/` 目录下读 `lxmod.json` → `AssemblyLoadContext`（可卸载）加载 `entry` → `ActivatorUtilities` 构造模块 → `Initialize(context)`；
3. 失败隔离：单模块加载/运行异常 → 导航项标错 + 日志记录，**不拖垮壳**（模块视图包在壳的异常边界内）；
4. 懒加载：`CreateMainView()` 首次切页才调用；`Shutdown()` 在退出时逆序调用。

### 10.4 版本兼容

- SDK 语义化：主版本 = 破坏性变更（接口签名改）；次版本 = 只增不改（模块断言 `sdk` 主版本 ≤ 壳的主版本即可加载）；
- 壳启动时校验：SDK 主版本不符 → 模块禁用并在设置页提示"需更新模块/工具箱"。

### 10.5 新模块最小示例（未来开发者 30 分钟上手）

```csharp
public sealed class HelloModule : ILxToolModule
{
    public string Id => "lx.hello";
    public string DisplayName => "示例工具";
    public string IconGlyph => "Sparkle24";
    public Version Version => new(1, 0, 0);
    public void Initialize(ILxModuleContext ctx) { /* 读设置/注册热键 */ }
    public FrameworkElement CreateMainView() => new HelloView();
}
```

放 `plugins/lx.hello/`（dll + `lxmod.json`）→ 重启即出现在导航。**这就是"留后续开发空间"的全部成本。**

### 11.3 兼容承诺

1. **servermonitor 协议**：`/servermonitor/report` 路由、`X-SM-Token` 头、快照 v:1 字段——工具箱只做"超集消费端"，任何官方 agent 版本上报都不得报错；
2. **QAS 数据**：旧 `devices.json` 自动迁移（8.5），迁移失败只警告不丢数据；
3. **设置文件**：`version` 字段单调递增，升级时写迁移器链（v1→v2→…），禁止原地破坏性格式变更。

## 12. 工程规范

- **分支**：`main`（可发布）+ `feat/<模块>-<主题>`；PR 需过 CI + 一名 review；
- **提交**：Conventional Commits（`feat(audio): …` / `fix(monitor): …`）；
- **版本号**：SemVer；模块版本独立于壳版本；
- **代码风格**：`dotnet format` + `.editorconfig`；公开 API 必须有 XML 文档注释（SDK 强制，CI 检查）；
- **XAML 规范**：样式只进 `LX.Ui` 资源字典；模块视图引用 `DynamicResource` 令牌，禁止硬编码色值/圆角。

## 15. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| `IPolicyConfig` 未公开接口被 Windows 更新改 vtable → 切设备失效 | 中 | 音频核心功能挂 | ① 切换前后各读一次默认设备做结果校验；② 预留 SoundSwitch 式多 vtable 探测；③ 失败时引导"打开系统声音设置"兜底 |
| LibreHardwareMonitor 内核驱动被杀软拦/需管理员 | 中 | 引擎 B 温度不可用 | 引擎 B 定位"可选增强"，默认引擎 A；温度缺失时 UI 隐藏该行（契约本就 nullable） |
| Win10 无 Mica → 玻璃观感打折 | 高（若有 Win10 用户） | 观感 | 三层降级链 Mica→Acrylic→纯色+玻璃卡片，令牌兜底色已备 |
| Toast 通知需包身份 | 中 | 通知体验 | v1 用托盘气泡；v1.1 评估 Velopack 包身份或 `DesktopToastsSample` 方案 |
| agent 外部进程依赖 Node/pkg exe 分发 | 低 | 监控引擎 A 部署 | 优先用官方 `build:exe` 产物内嵌/随包下载；失败时设置页给官方 install 脚本引导 |
| 单文件自包含体积失控 | 已发生（QAS） | 分发 | 13.3 发布策略 + CI 产物体积阈值告警 |
| 端口 2536 被占用 | 低 | Hub 起不来 | 启动检测占用 → 自动顺延 2537…2539 并写设置页 |
